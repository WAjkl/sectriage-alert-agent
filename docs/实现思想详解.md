# 实现思想详解

> 这份讲的是**为什么这么设计**，不是"怎么跑"。适合背下来应付追问。
> 代码在 `app/` 下，六个文件，每个都不长。

---

## 0. 一条总原则：三层分离 + 四个硬边界

```
app/config.py     配置        所有环境变量、路径、网段台账
app/store.py      数据        只读写，不做判断
app/retrieve.py   检索        bigram / BM25 / RRF
app/pipeline.py   业务        聚合 → 富化 → 研判 → 决策
app/api.py        接口        只做参数校验和调用
main.py           入口        起服务 + 首次自动造数据
```

**四个硬边界**（这块是"可维护"和"能跑"的分水岭）：

| 层 | 只做什么 | 明确不做什么 |
|---|---|---|
| `aggregate` | 看时间与实体，把告警并成事件 | 不看内容语义、不做真假判断 |
| `enrich` | 补上下文（资产/历史/网段） | 不做判断 |
| `triage` | 出"真假 + 置信度 + 依据" | **不执行任何动作** |
| `decide` | 路由（自动关/升级/转人工） | **不重新判真假** |

**好处**：每层都能单测；线上出问题能立刻定位是哪一层的锅（判错了是 triage，动作错了是 decide）。

> 面试可讲："我把'判断'和'动作'拆成两层，因为它们的失败代价不一样——判错可以改，动作错了删不回来。"

---

## 1. 为什么是工作流，不是 Agent

**判据只有一条：步骤能否枚举。**

本项目的步骤：接入 → 聚合 → 富化 → 检索 → 研判 → 路由 → 审计。**全都能枚举** → 它是工作流。

**为什么要显式选工作流**（成本账）：

| 方案 | 调用次数 | token | 一致性问题 |
|---|---|---|---|
| 逐条研判 | 3000 次 | ≈ 240 万 | 同一波爆破刷 600 条 → 可能给出 600 个不同结论 |
| 先聚合再研判 | 40 次 | ≈ 4.8 万 | 一个事件一个结论 |

**省 98% 的调用，而且结论一致。**

> 面试可讲："我先做确定性管线，只把'这个事件到底是不是真的'交给模型。什么时候该上 Agent？高严重级、核心资产、证据缺失这三种情况——因为那时多花 3 倍钱值得。"

## 2. 聚合层：为什么用实体指纹，不用语义

```python
fingerprint = 资产 | 归一化源IP | 规则 | 技术
```

**四个字段各自解决什么**：

| 字段 | 如果不加会怎样 |
|---|---|
| 资产 | 同一攻击打跳板机和打数据库会被合并成一个事件 |
| 源 IP | 两个 IP 同时爆破会被合并，丢掉"多源"这个信号 |
| 规则 | 同一台机上的"暴破"和"Web 扫描"是两个战术阶段，不能混 |
| 技术（ATT&CK） | 规则名可能不同但本质同一技术，加它能跨规则聚合 |

**为什么要归一化 IP**：真实日志里是 `45.12.33.7:52341`、`45.12.33.7:52399`——同一个源。不归一化会炸成几百个簇，降噪失效。

**为什么不用语义/LLM 聚合**（这条最容易被追问）：

1. **确定性**：同样输入必须同样输出。安全场景不能接受"这次 50 个簇、下次 47 个"——你没法解释。
2. **可解释**：能指着指纹说"因为它们资产相同、源 IP 相同、规则相同、时间相邻"。
3. **成本**：规则是毫秒级 + 免费。
4. **语义模型会犯错**：两条告警文本几乎一样（都是 `Failed password for root`），但一条内网、一条境外——**语义相似度会把它们合成一个事件，这是硬伤**。

> 一句话版本："**聚合看实体，研判看语义。用错层次就会把'内网管理员登录'和'境外爆破'合成一个事件。**"

**时间窗 10 分钟怎么来的**：自动化爆破一般持续几分钟到几十分钟。太短（1 分钟）一次攻击被切成十几个簇；太长（1 小时）上午探测和下午攻击被合并，丢掉事件边界。

**乱序必须处理**：真实告警因采集延迟会乱序到达，所以聚合前**先按时间排序**（`group.sort(key=_ts)`），否则窗口判断全错。

## 3. 富化层：上下文为什么值钱

同样一条 "SSH 暴力破解"：

| 打在哪 | 处置 |
|---|---|
| 跳板机（重要性 3，公网） | 封 IP + 看是否成功登录 |
| 核心数据库（重要性 5，内网） | **立即隔离 + 排查横向 + 上报** |

**只靠 severity 判断不了这个差别**——必须补资产属性。

**这里踩过一个真坑（面试可以讲）**：

我一开始用 **IP 前缀**判内外网（`10. / 192.168. / 172.`）。真实靶场一跑就错了两处：

- `127.0.0.1` **不在前缀表里** → 本机的监控/备份流量被当成"外部攻击"（两个误报）
- `172.24.x` 是 WSL 的 NAT 段，落进 `172.` 前缀 → 被当成"内网" → **真正的扫描攻击被漏掉了**

**结论**：IP 段是网络层的概念，业务上的"内外"要靠**资产台账**（`config.ZONE_RULES`）。这也是为什么 `zone_of()` 读的是台账而不是 RFC1918 判断。

> 这句话很加分："**合成数据发现不了这个问题，因为 IP 是我自己编的，天然符合我写的规则。**"

**历史频次**：同指纹过去出现过几次。注意它是**降权信号，不是判决依据**——天天被爆破也会出现很多次，那不代表是误报。

## 4. 检索层：为什么 bigram + BM25 + RRF

**为什么不上向量库**：这个项目的 SOP 只有 6 条。装 Chroma/PGVector 是过度设计（多一个服务、多一份运维）。**接口签名 `retrieve_sop(query, k)` 就是稳定边界**，以后换向量库只改这个文件。

**为什么要两路**：向量懂语义但漏编号，BM25 懂编号但漏同义。实测（另一个项目的对照实验）：

| 方案 | R@1 | 难例 R@1 |
|---|---|---|
| 纯 bigram 向量 | 0.740 | 0.381 |
| BGE 语义向量 | 0.825 | 0.429 |
| BGE + BM25 + RRF | **0.832** | 0.333 |

**为什么要 RRF 而不是分数相加**：余弦是 0–1，BM25 无上界。直接加会让 BM25 通吃。RRF 只用排名（`Σ 1/(k+rank)`，k=60），免疫量纲。

**RRF 的代价**（主动说）：丢掉分差信息。当两路质量差距很大时，等权融合会把差的那一路拉进来——实测在 32 篇小语料上混合反而比纯向量差 9.5 个点，80 篇才反超。**"混合一定更好"是错的。**

## 5. 研判层：三条纪律

```python
{"verdict": "true_positive|false_positive|need_human",
 "confidence": 0.0~1.0,
 "reason": "≤60字",
 "sop_id": "SOP-01"}
```

| 纪律 | 为什么 |
|---|---|
| **必须结构化 JSON** | 自由文本没法进决策逻辑，也无法写审计 |
| **必须给置信度** | 研判本质是不确定决策；没有置信度就只能"全自动"，风险不可控 |
| **必须给证据引用** | "判为误报"没价值；"判为误报，依据 SOP-04 且源主机是备份服务器"才能审计 |

**第四条（最容易被忽略）**：**给模型弃权的权利**（`need_human`）。
不给弃权选项，它就会硬判；安全场景里**硬判比不判危险**。提示词里明确写了"证据不足时必须降低 confidence 或直接判 need_human"。

**temperature = 0**：研判要可复现。同一事件跑三次结论不一致，没法跟人解释。

**降级路径**（`triage()` 里的 `try/except`）：模型挂了走 `_rule_based`，标 `mode=fallback_rule` 并带 `error`。
**不是把异常吞掉**，而是让上层知道"这次不是模型判的"。

**规则基线为什么故意写得笨**：只 `severity` + `zone`。因为基线要是全对，就说明我把答案写进去了（第一版就犯过这错，准确率 100%，明显是作弊）。

## 6. 决策层：人机边界画在哪

```python
if v == "false_positive" and conf >= 0.8 and imp <= 3:  → auto_close（可自动）
if v == "false_positive" and conf >= 0.8:               → need_human（核心资产不自动关）
if v == "true_positive" and conf >= 0.8 and imp >= 4:   → escalate（要人确认）
if v == "true_positive" and conf >= 0.8:                → review（低价值资产，建议排查）
else:                                                    → need_human
```

两条铁律：

1. **只有"可逆、低风险"的动作才自动执行**。标记误报是可逆的；封 IP、隔离主机不可逆。
2. **核心资产（重要性 ≥4）的误报也不自动关**——丢掉一条核心资产的告警，代价可能是一次漏报。

> 面试可讲："**AI 只做建议和分级，写操作永远有人签字。**这不是技术限制，是工程原则。"

## 7. 接口层为什么这么薄

`api.py` 只做三件事：参数校验（Pydantic/Query）、调 pipeline、返回 JSON。

**为什么不把逻辑写进路由**：换 Web 框架（FastAPI → Flask）时只改这一个文件；而且业务函数能被单测直接调用，不需要起 HTTP。

**统一错误出口**：

```python
@app.exception_handler(Exception)
async def on_error(request, exc):
    return JSONResponse(500, {"error": exc.__class__.__name__, "detail": str(exc)[:200]})
```

**不把堆栈吐给调用方**——生产环境堆栈里可能有内网路径。

## 8. 单测覆盖了什么（14 个，跑 0.07 秒）

只测**纯函数**，不测 HTTP、不调 LLM——这类测试快、稳、改代码时真能拦住问题。

| 测试 | 拦的是什么错 |
|---|---|
| `test_norm_ip_strips_port` | 忘了去端口 → 簇数爆炸 |
| `test_fingerprint_differs_by_technique` | 少一个字段 → 合并错事件 |
| `test_aggregate_splits_over_window` | 窗口失效 → 把两次攻击并成一个 |
| `test_aggregate_handles_unordered_input` | 忘排序 → 窗口判断全错 |
| `test_decide_auto_close_only_low_value` | 核心资产误报被自动关 → 会出事 |
| `test_zone_uses_ledger_not_rfc1918` | 用 IP 前缀判内外网 → 漏报（真踩过） |

> 面试可讲："我挑的都是**曾经真的会出错**的点来写测试，不是为了凑覆盖率。"

## 9. 一个可交付项目的要素清单

对照一下，缺哪项就说明还停在 demo：

| 要素 | 本项目 | 为什么必须有 |
|---|---|---|
| 一键启动 | `start.bat` / `python main.py` | 面试官不会陪你配环境 |
| 依赖锁定 | `requirements.txt` 带版本号 | 不锁版本，三个月后跑不起来 |
| 配置与代码分离 | `.env.example` + `config.py` | 密钥不能进代码 |
| 单测 | `tests/` 14 个 | 证明你懂"改一处不炸别处" |
| 容器化 | `Dockerfile` + `compose` | 部署的一致性 |
| 统一错误处理 | `exception_handler` | 不泄露堆栈 |
| 数据与代码分离 | `data/` 且 gitignore 生成物 | 仓库不该有 3000 行模拟数据 |
| LICENSE | MIT | 别人敢用 |
| README 有"已知局限" | 见 README | 主动暴露短板比被挖出来强 |
| 首次运行自解释 | 没数据自动生成 | 新手不会卡在第一步 |

## 10. 如果要上生产，还缺什么（主动说）

1. **存储**：现在读 JSONL，上万事件要换 SQLite/ES，且要加索引
2. **历史库**：`history_clusters` 只统计当前批次，真实要查 7 天
3. **跨事件记忆**：同一 IP 打了三次仍是各判各的（Agent 版有部分改善，但没有持久化）
4. **告警源接入**：现在只有自造数据 + 靶场，没有对接真实 EDR/WAF
5. **压测**：100 QPS 卡在哪没测过
6. **前端**：单页够演示，不够值班用（没有批量操作、没有详情页）

> 能主动说出这六条，比多报 10 个百分点更值钱——因为它证明你知道"生产"和"能跑"的区别。

## 附：十个自问自答（面试前过一遍）

| 问 | 一句话 |
|---|---|
| 为什么不用 Agent 做聚合 | 语义会把内网登录和境外爆破合成一个事件；且要确定性 |
| 时间窗为什么 10 分钟 | 自动化爆破持续几分钟到几十分钟；太短切碎太长丢边界 |
| 为什么必须排序 | 告警乱序到达，不排序窗口判断全错 |
| 归一化 IP 干什么 | 去掉 `:port`，否则同一源炸成几百个簇 |
| 为什么 RRF 不用加权 | 余弦 0–1、BM25 无上界，加权要调参数且换数据就废 |
| 置信度怎么用 | 低于 0.8 转人工；没有它就只能全自动，风险不可控 |
| 为什么给模型弃权权 | 不给就会硬判；安全场景硬判比不判危险 |
| 核心资产误报为什么不自动关 | 丢一条核心资产告警可能是一次漏报 |
| IP 前缀判内外网错在哪 | 127 不在表里；172.24 是 NAT 段却被当内网 → 漏报 |
| 你的基线为什么这么低 | 故意的。基线全对说明把答案写进去了 |
